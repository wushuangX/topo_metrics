## 二、提示词定义与背景分析

### APLS 指标 (Average Path Length Similarity)

- **定义/目的**：APLS 是一种基于图论的道路网络评估指标，用于衡量预测道路图与真值道路图之间的拓扑相似度。它计算真值图与预测图中节点对之间最短路径长度之差的累积，并归一化得到0到1之间的分数【6†L379-L387】【51†L7-L14】。分数越高表示预测图与真实图在连通性和路径长度方面越接近，缺失重要连接会显著降低分数【6†L379-L387】【51†L7-L14】。

- **理论背景**：APLS 最早由Van Etten 等人在SpaceNet竞赛中提出，并在相关博客和论文中详细说明【51†L7-L14】【6†L379-L387】。其理论基础源于最短路径（Shortest Path）分析，关注节点之间连通路径的长度差异，以反映道路网络的拓扑结构保真度。与传统像素级F1不同，APLS 更重视网络连通性对路径规划的重要性【6†L379-L387】【51†L7-L14】。

- **应用场景**：主要用于遥感道路提取和道路图重建任务的评估，例如SpaceNet、RoadTracer等竞赛和研究中常采用APLS来评价算法提取的道路连通性是否完整。其也可推广应用到任何需要评估连通图预测质量的领域，如城市交通网络提取、细胞神经网络重建等。

- **优点/强弱势**：APLS 对高中心性节点（关键路口）丢失较为敏感，能凸显主要通路的连通性问题【6†L379-L387】【51†L7-L14】。该指标对小区域内的局部误差不敏感，适合评估大范围网络拓扑一致性；但计算时需从预测掩膜构建图并运行Dijkstra等算法，计算成本较高，实时性较差。APLS 无法考虑几何位置误差细节，只关注路径长度，与边权设定相关（可采用距离或时间权重）【6†L379-L387】【51†L7-L14】。

- **示例改进提示**：  
  - *简洁版*：“定义APLS指标并说明其应用”。  
  - *详细版*：“请解释平均路径长度相似度（APLS）指标的定义、计算方法，以及它在道路提取任务中的作用，并提供参考文献【6†L379-L387】【51†L7-L14】。”  
  - *领域版*：“在遥感道路网络评估中，如何利用APLS度量来比较预测图与真实路网？请给出公式、示例场景和优缺点【6†L379-L387】【51†L7-L14】。”  

- **验证评估**：可通过在已有路网数据集（如SpaceNet标签）上测试不同预测结果，计算APLS值与其它指标（如IoU）进行对比，验证预测连通性的改进与否。对Prompt 成效，可比较模型回答是否正确包含APLS定义、公式和引用，或通过问答评分标准（准确性、全面性）进行人工评审。

### TOPO 指标（拓扑精度与召回，Topology F1）

- **定义/目的**：TOPO 指标是一种局部拓扑相似度度量，通过在每个种子节点周围的一定“孔洞大小”范围内比较预测图与真实图中可达节点来评估图相似性【17†L397-L404】。具体地，随机选取若干真值图中的关键节点，考察在该节点周围一定距离内预测图是否具有对应的连通节点，以计算局部的真阳性/假阳性/假阴性，再综合得到精度、召回或F1值。

- **理论背景**：TOPO 由Van Etten 等在SpaceNet竞赛工作中提出【17†L397-L404】，主要思想是关注小范围内的连通关系，而非全局路径。与APLS比较全局路径不同，TOPO 强调物理距离缓冲区内是否保持通路连通性，对局部拓扑结构有良好评价作用【17†L397-L404】。最初TOPO由论文[5]提出（可参考Van Etten的研究）并被随后工作采用。

- **应用场景**：同样用于遥感道路网络评估，尤其关注小范围邻域的连通性。如评价算法是否能在局部区域内正确恢复路口结构和短距离连通性。TOPO 常与APLS一起使用，可以补充APLS对局部拓扑细节敏感度不足的问题。

- **优点/弱点**：TOPO 评估局部邻域连通性，对于距离较远的连通关系不作度量【17†L397-L404】；对节点空间偏移有一定鲁棒性。缺点是TOPO的范围参数（孔洞大小）需要经验设定，并且如果预测图有长距离断裂但局部仍连通，TOPO可能仍给高分。此外TOPO无法比较路段的长度或权重，仅关注节点连通。相比APLS其计算较快，适合中小尺度测试【17†L397-L404】。

- **示例改进提示**：  
  - *简洁版*：“什么是TOPO指标？”。  
  - *详细版*：“请详细解释TOPO度量（Topological Precision/Recall 或 Topological F1）在道路网络评估中的含义、计算步骤，以及如何在实际评估中使用【17†L397-L404】。”  
  - *领域版*：“在道路提取任务中，TOPO评估如何度量预测图和真值图的拓扑差异？请说明种子节点、孔洞参数和结果解释【17†L397-L404】。”  

- **验证评估**：可对同一预测输出计算不同孔洞大小下的TOPO精度/召回，分析连通性敏感性。对Prompt优化，可检查回答是否阐明了TOPO的分类（TP/FP/FN定义）、缓冲区等细节，并是否给出应用实例。

### Graph IoU 指标

- **定义/目的**：Graph IoU（图交并比）将道路网络图渲染为二值像素图，然后计算预测与真实图像的IoU（交并比）【13†L548-L556】。具体操作是：根据一定阈值将图中节点/边点扩展为二值像素，然后直接计算像素层面的交并比。

- **理论背景**：该指标源于车道/道路图预测领域，常用于自动驾驶车道线评估，如LaneGNN等工作【13†L548-L556】。由于直接在像素上计算，可借鉴语义分割IoU评价方式，但在图形层面考虑一点偏差（距离阈值d）仍被视为匹配【13†L548-L556】。

- **应用场景**：用于车道线和道路网络的整体质量评估，尤其是在自动驾驶地图生成场景中。适合快速对比不同方法在像素层面的整体覆盖一致性。

- **优点/弱点**：Graph IoU 计算简单、速度快，可兼容像素级评价框架；但它忽视拓扑结构细节，例如连通性和路径长度，相当于将图问题转换为分割问题【13†L548-L556】。在局部结构错位或缺少关键连接时，Graph IoU 可能仍然得高分，因此不适合单独衡量网络连通性。【13†L548-L556】特别指出，当图预测难度增大时，Graph IoU 会急剧下降，表明它对节点对齐精度敏感。

- **示例改进提示**：  
  - *简洁版*：“请定义Graph IoU指标并说明其用途”。  
  - *详细版*：“什么是Graph IoU？请解释其计算方法（包括如何将图转为二值图），并讨论该指标在车道或道路图评估中的意义【13†L548-L556】。”  
  - *领域版*：“在道路或车道图提取任务中，Graph IoU如何衡量预测图与真实图的相似度？请描述像素渲染和IoU计算过程【13†L548-L556】。”  

- **验证评估**：通过生成示例图（如图中一些连通缺失情况）计算IoU值，对比不同案例下Graph IoU的变化，验证其是否反映了图形的一些偏差。此外可以与APLS等指标对比，以检验哪些错误Graph IoU无法捕捉。提示词成效可通过问答准确性（是否提到渲染过程和阈值）评估。

### 图编辑距离 (Graph Edit Distance, GED)

- **定义/目的**：图编辑距离是一种通用的图相似度度量，通过计算将一个图变换为另一个图所需的最小编辑操作（如节点/边的插入、删除、替换等）的代价来衡量两个图的相似性【53†L123-L130】。距离越小表示两个图越相似。

- **理论背景**：GED 源自图论和模式识别领域，是字符串编辑距离的推广【53†L123-L130】。1970年代被形式化，用于图模式匹配、结构对比等各种图数据比较场景。一般需要定义每种编辑操作的代价，并求解最小代价路径，其计算复杂度很高（NP难问题）。

- **应用场景**：在需要严格比较图结构相似度的场合，例如社交网络对比、化学分子图相似搜索等，可使用GED。虽然在道路或血管结构评估中不常直接使用（因计算复杂度较高），但可以作为一种理论参考或小规模验证工具。

- **优点/弱点**：GED 可精确捕捉结构差异，对每个节点/边差异都有量化惩罚。但其缺点是：计算开销大（一般需要搜索大量编辑序列），对大型图不适合；编辑代价选择敏感，结果依赖具体代价设置【53†L123-L130】。在图预测评估中，直接应用GED很难对规模较大的道路网或神经网络有效计算。

- **示例改进提示**：  
  - *简洁版*：“什么是图编辑距离？”。  
  - *详细版*：“请介绍图编辑距离(GED)的概念与计算方式，包括常见的图编辑操作和代价定义【53†L123-L130】。”  
  - *领域版*：“在评估两个道路网络图结构差异时，如何利用图编辑距离度量其差异？请说明GED的编辑操作类型和意义【53†L123-L130】。”  

- **验证评估**：可设计简单图示例（小型图）验证GED计算结果，例如对一个图进行节点/边删除，看GED结果是否反映编辑次数。提示词评价可检查回答是否提及代价最小编辑路径、对应公式或定义。

### Betti 数目误差与 Betti 匹配误差

- **定义/目的**：Betti 数目误差（β_err）和 Betti 匹配误差（μ_err）是基于拓扑不变量（Betti 数）的评估指标。Betti 数（Betti numbers）表示连通分支数、环路数等拓扑特征数目。β_err 计算预测图和真实图的 Betti 数差异；而 μ_err（Betti 匹配误差）提出基于持久同调条形码的一致匹配方法，可以更准确匹配真实与预测的拓扑特征【28†L67-L73】。

- **理论背景**：Stucki 等人（2022年）提出Betti匹配概念，用持久同调（Persistent Homology）分析图形，克服仅比较Betti数无法捕捉位置差异的局限【28†L67-L73】。他们证明Betti匹配更敏感且可差分，用于评价分割结果的拓扑正确性【28†L67-L73】。这些指标强调空间上对应拓扑特征的一致性。

- **应用场景**：主要用于医学/生物图像分割中评价结构连通性（如神经纤维或血管结构）。Betti数用于量化目标区域的分支/洞数量，Betti匹配误差适用于需要空间精确度的场合。比如评估血管分割是否漏连了某根血管（连通性）或多加了假洞。

- **优点/弱点**：Betti误差简单，只比较总数；但对不同位置或重排的拓扑特征鲁棒性差（不同分支个数相同也无法区分）。Betti匹配改善了这一点，能够对齐真实和预测的拓扑特征，但计算复杂，需要计算匹配问题，对噪声敏感【28†L67-L73】。两者通常作为补充指标以揭示Dice类指标忽略的拓扑差异。

- **示例改进提示**：  
  - *简洁版*：“什么是Betti数目误差？”。  
  - *详细版*：“请解释Betti数目误差和Betti匹配误差的含义，以及它们在图像分割拓扑评估中的作用【28†L67-L73】。”  
  - *领域版*：“在血管分割任务中，如何使用Betti数（连通分支数）来评估结果？请比较传统Betti误差与Betti匹配的方法【28†L67-L73】。”  

- **验证评估**：可通过制造简单示例（如真实图有1条连通分支，预测图分支变多）计算β_err；并对比含有位移或细微拓扑错误的案例，看μ_err是否更能反映问题。Prompt 的质量可通过回答中是否说明持久同调匹配算法和灵敏度进行评估。

### 中心线Dice（clDice）指标及损失

- **定义/目的**：中心线Dice（clDice）是一种拓扑感知的相似度度量，针对细长、管状结构（血管、道路等）分割。它通过将分割结果与其骨架进行比较来度量相似度【24†L14-L22】【45†L100-L109】。公式上，clDice 考虑分割掩码与其骨架交集与覆盖情况（类似Dice系数），从而保证连通性。作者证明clDice从拓扑视角对拓扑同伦等价保持有理论保证【24†L14-L22】。

- **理论背景**：Shit 等人在 CVPR2021 提出clDice【24†L14-L22】，为常见的Dice和IoU等面积指标提供拓扑补充。其软可导版本（soft-clDice）可作为损失函数，用于训练网络**显式**优化连通性【24†L14-L22】【22†L540-L549】。clDice在多个数据集（道路、血管、神经等）测试中证明能改善拓扑准确度【24†L14-L22】【22†L540-L549】。

- **应用场景**：广泛用于医学血管、神经纤维分割，以及遥感道路分割中强调连通性的训练和评估。任何管状结构分割任务都可采用clDice以加强连通性。实际应用中，将soft-clDice与传统Dice结合，以同时优化面积和拓扑指标。

- **优点/弱点**：clDice 能有效保留管状结构的连通信息，相对于Dice提升了连通性评价【24†L14-L22】【22†L542-L551】。缺点是计算clDice需对分割结果进行骨架化（骨架精度可能受噪声影响），因此计算成本高于普通Dice。在训练中，soft-clDice需要迭代形态学操作近似骨架，增加计算量【22†L540-L549】【44†L19-L28】。同时，clDice并非对所有拓扑错误敏感，如复杂环路可能仍被忽略。

- **示例改进提示**：  
  - *简洁版*：“中心线Dice（clDice）是什么？”。  
  - *详细版*：“请详细说明中心线Dice(clDice)指标的定义、计算方法及其在管状结构分割（如道路/血管）的评估意义【24†L14-L22】。”  
  - *领域版*：“在道路/血管分割任务中，如何使用clDice度量分割质量？请说明其与传统Dice的区别，以及soft-clDice损失如何实现连通性优化【24†L14-L22】【22†L540-L549】。”  

- **验证评估**：可比较同一模型使用交叉熵损失与soft-clDice联合损失的输出，观察连通性指标（如连通组件数）变化。可用已有分割结果计算clDice与Dice的数值差异，评价clDice对连通性的敏感性。Prompt 效果可检查回答是否涵盖clDice保证同伦等价、计算需要掩码和骨架等关键点【24†L14-L22】。

### 骨架召回损失（Skeleton Recall Loss）

- **定义/目的**：Skeleton Recall Loss 是一种新的拓扑损失，旨在保持细长结构的连通性。它先预计算真值掩膜的“管状骨架”（包括骨架及其周边像素），然后计算预测掩膜在该骨架上的soft Recall，从而避免在训练时对预测进行昂贵的骨架化【46†L19-L27】【46†L73-L81】。该损失主要惩罚预测未覆盖真值骨架的情况，保持连通结构。

- **理论背景**：Kirchhoff 等人在2024年提出该损失【46†L19-L27】。与clDice等需可微分骨架化不同，骨架召回损失仅在真值（或预处理）上使用骨架，大幅减少计算开销【46†L19-L27】。论文指出，该方法在5个不同数据集上优于clDice等已有损失，并特别适用于多类分割问题【46†L19-L27】【46†L123-L132】。

- **应用场景**：主要用于医学（血管、神经）和道路裂缝等细长结构的分割训练。由于无需对预测进行GPU骨架化，非常适合大体积或多类场景。可代替或结合clDice来进一步提升连通性。

- **优点/弱点**：优点是计算高效（CPU预处理）且易于扩展到多类场景，不需要额外网络改动【46†L19-L27】【46†L123-L132】。缺点是依赖于真值骨架的质量，如果预计算骨架有误或参数选择不当，可能影响效果；对预测出现额外连通时不直接惩罚，只关心漏检部分。

- **示例改进提示**：  
  - *简洁版*：“什么是Skeleton Recall Loss？”。  
  - *详细版*：“请解释骨架召回损失（Skeleton Recall Loss）的原理和设计动机，包括如何利用真值掩膜的骨架进行损失计算【46†L19-L27】。”  
  - *领域版*：“在细长结构分割（如血管、道路）中，Skeleton Recall Loss如何帮助保持连通性？请描述其与clDice损失的主要区别及计算流程【46†L19-L27】。”  

- **验证评估**：通过对比使用标准损失、clDice损失和Skeleton Recall损失训练模型输出的连通性指标（如漏分支率、连通组件数），评价其作用。Prompt验证可检查回答是否提到“管状骨架”、“soft recall”、以及性能优势等要点【46†L19-L27】【46†L123-L132】。

### CAPE 损失（Connectivity-Aware Path Enforcement）

- **定义/目的**：CAPE是一种连通性感知的损失函数，通过比较整个路径的连通性来增强分割结果的拓扑正确性【42†L71-L79】。具体做法是：从Ground Truth图中选节点对，利用Dijkstra算法找到真值图中的最短路径，然后将该路径映射到预测掩膜上，计算预测路径覆盖率，以此衡量连通性误差【42†L71-L79】。

- **理论背景**：Esmaeilzadeh 等人在 MICCAI 2025 提出CAPE【42†L71-L79】。其设计灵感来自于APLS，将连通性损失直接嵌入训练过程。CAPE直接对比预测掩膜与真值路径，显式惩罚连通性中断，比像素级损失关注更高层次的拓扑一致性【42†L71-L79】。

- **应用场景**：主要用于薄管结构（如神经纤维）和道路网络分割的训练，尤其在保持长距离连通时表现突出。适合需要严格保证路径完整性的任务，如医院血管分割或路网提取。

- **优点/弱点**：CAPE 强调**全路径**连通性，避免模型生成断裂路径【42†L71-L79】。但其计算依赖Dijkstra，训练时成本较高。论文指出，相比仅使用clDice等局部损失，CAPE 生成的连通结构更完整、误分裂更少【42†L71-L79】。劣势是计算复杂度和对超参数（如选定节点对的范围）敏感。

- **示例改进提示**：  
  - *简洁版*：“CAPE损失是什么？”。  
  - *详细版*：“请解释CAPE (Connectivity-Aware Path Enforcement) 损失的原理，包括如何将APLS的思想融入网络训练，以及它对分割连通性的影响【42†L71-L79】。”  
  - *领域版*：“在医学血管或道路网络分割中，CAPE损失如何评估和改善连通性？请描述基于Dijkstra路径比较的具体步骤【42†L71-L79】。”  

- **验证评估**：可设计实验：对比使用和不使用CAPE损失的模型输出，检查漏断路径率和连通组件数目。Prompt质量可通过回答中是否提及最短路径映射、连通性比对等关键步骤来评估。

### 其他指标与损失（简要提及）

- **连通性度量（Connectivity Score）**：常用来评价分割结果中是否连通，计算预测掩膜连通组件数是否与真值一致。常作为复合指标，没有统一标准公式，一般结合特定任务规则定义。
- **端点/路口匹配指标**：在道路分割中评估预测图中路口（交点）或端点位置与真值的匹配情况，可计算端点距离误差或匹配准确率。
- **几何距离指标**：如Hausdorff距离、Chamfer距离等评估预测分支对齐精度，与拓扑指标可互补。
- **路径相似度指标**：除了APLS，可使用预测与真值网络间的“最短路径覆盖率”或“路径长度比”等简化度量。
- **持久同调损失**：基于Betti或持久图匹配的可微分损失函数（如Hu 等提出的方法）可用于直接优化目标拓扑特征，理论复杂但可以纳入训练。

以上提示词中涉及的技术领域偏重 **深度学习模型** 和 **拓扑图结构评价**。在实际Prompt设计时，使用专业术语并确保清晰任务描述是必要的。

## 三、提示词分类与比较

我们将提取的提示词按照任务性质和目标进行分类，主要聚焦于**信息检索/总结提示**和**指导研究/实验提示**两类。下表对不同类别提示词的建议结构、典型长度、温度设置和期望输出进行了汇总对比：

| 提示词类别     | 建议提示结构                                  | 典型长度/Token 数量 | 温度建议   | 期望输出形式                          |
|--------------|----------------------------------------------|--------------------|----------|------------------------------------|
| **指标解释型**（定量分析）<br>（如“APLS 定义”、“clDice 含义”） | 问句或任务说明 + 关键术语<br>建议包含定义求解、背景、示例说明 | ~10–20词         | **0.0–0.3**（准确性要求高） | 规范的技术解释段落，含公式说明，引用来源；             |
| **对比分析型**（比较指标/方法）<br>（如“APLS vs TOPO”） | 问题格式 + 要求对比的两个项名称<br>如“比较 A 和 B 的异同” | ~15–30词         | **0.0–0.3** | 对比性说明，分段阐述各项优势劣势，给出结论和引用；     |
| **实践应用型**（应用场景/示例）<br>（如“APLS 在道路提取中的应用”） | 请求示例或应用说明的句子<br>最好指明领域上下文       | ~10–20词         | **0.0–0.3** | 涵盖具体应用场景的说明，结合实际数据集或案例；            |
| **搜索查询型**（构造检索关键词）<br>（如“APLS metric road extraction”） | 关键词组合，无需完整语句，可多关键词并列              | 2–6 词/项        | 无（非生成任务） | 适合用作搜索引擎查询词，不产生直接输出。                 |
| **总结归纳型**（列点/表格）<br>（如“列出道路网络指标”） | 要求列表或表格形式的提示，往往以“列出”、“总结”开头    | ~5–15词         | **0.0–0.3** | 列表或表格形式输出，每项简短说明或示例。                 |
| **提示工程型**（AB测试提示设计） | 说明提示优化需求，如“设计提示模板”、“比较提示效果”等   | ~10–20词        | **0.2–0.5**（引发对话） | 给出详细的提示设计方案、实验步骤或提示模板示例。         |

- **典型结构**：指标解释型和对比分析型提示应以完整问句或说明句开头，突出任务和对象（如定义哪个指标、比较哪些方法）；实践应用型可简略提及场景；总结归纳型适合使用动词“列出”、“总结”；搜索查询型则仅包含关键词。  
- **长度**：技术性提示一般不超过30词，否则可能引起混淆；列表型或关键词型可很短。  
- **温度/参数**：对于需要准确、权威答案的提示（如定义、比较），推荐低温度（0.0–0.3）以确保输出稳定一致，并可考虑设置较高的`top_p`以扩展答案深度；对于多步生成或创新提示，可适当提高温度（0.3–0.5）鼓励详细回答。  
- **期望输出**：多数为技术性段落或分项解释，需要包含定义、背景、应用或对比要点，并援引权威来源。输出应条理清晰，避免冗余；对技术名词给出中文或英文解释。

## 四、提示词优化与迭代框架

基于前述分析，我们提出以下迭代优化提示的框架和方法论，以系统设计和评估提示词变体：

1. **初始提示设计**：基于目标任务（指标解释、方法比较等），撰写一个基础提示。例如：“请解释APLS指标的定义和作用【6†L379-L387】。”  
2. **生成变体**：为同一任务构建多种提示版本（如上文的简洁版/详细版/领域版）。保持核心内容一致，但调整措辞长度和上下文细节。例如，把需求扩展为“请详细说明APLS的定义、公式和应用场景”。  
3. **执行A/B测试**：针对每组提示变体，在相同条件下调用模型获取回答。可使用多个不同随机种子或不同模型（若可用）执行多次采样。  
4. **评价指标确定**：建立对模型回答的评价标准，包括：  
   - 内容准确性（是否正确解释了概念、包含公式和引用）  
   - 完整度（是否涵盖所有要求的方面，如定义、背景、应用）  
   - 可读性（条理清晰、语言流畅）  
   - 事实支持（是否包含了引用的断言，如文献出处）。  
   可以设计**量化指标**：如回答中正确术语或公式的数量占比、参考文献数量，以及**人为打分**。  
5. **统计分析**：收集各提示变体对应的多组回答评价，使用统计方法（如t检验、置信区间等）比较不同提示的平均分数，判断改进是否显著。  
6. **收敛与迭代**：选出效果最佳的提示变体作为新基准，进一步微调（如增加示例、限定格式、改变语气）。重复步骤3–5，直到性能指标提升趋于稳定或达到预期目标。  
7. **成功标准**：定义明确的成功准则，例如回答中必须正确包含定义、背景、应用等核心要素；或回答达到人工评分阈值。样本量充足时，可用**A/B测试的显著性**（p-value<0.05）判定提示优劣。

以上流程如图所示：

```mermaid
flowchart LR
  A[确定初始提示] --> B[生成提示变体]
  B --> C{对话模型执行}
  C --> D[收集回答输出]
  D --> E[自动/人工评估]
  E --> F[对比分析 (统计测试)]
  F --> G{是否改进?}
  G -- 否 --> H[结束：选择最佳提示]
  G -- 是 --> B
```

**实验示例**：以“APLS定义”任务为例，我们可以设计以下实验：  
- Baseline：问“APLS是什么？”；  
- 变体1：问“请解释APLS（平均路径长度相似度）指标的含义和计算方法，并举例说明【51†L7-L14】。”；  
- 变体2：在问题前加入上下文如“在遥感道路网络评估中，…”；  
对比这些问题的回答，检查哪种提示提供的解释最完整准确，包括是否给出公式、论文引用等。

使用**统计方法**（如多次对话回答评分后进行t检验）来验证不同提示的改进是否显著。总结优化结论并据此调整提示。

## 六、评估与后续实验建议

为了验证提示优化的有效性，我们建议如下评价方案：

- **评价指标**：准确度（回答中信息是否正确）、完整度（回答覆盖要点）、流畅度。可以采用**人工评分**（专家打分）或设计**问答测验**（检查回答是否包含关键术语和公式）。对代码类输出，可验证逻辑正确性。  
- **成功标准**：回答中应至少包括提示中要求的所有内容项，并且主干信息与权威资料一致。例如，解释APLS的回答需要出现路径长度差、0–1分值和参考【51†L7-L14】【6†L379-L387】。  
- **统计方法**：对于多次对话结果，可用统计测试（如t检验或bootstrap置信区间）比较不同提示的平均评分，以判断改进是否显著。
