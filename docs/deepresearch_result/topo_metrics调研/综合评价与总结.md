## 二、各模型详细评价

### 2.1 ChatGPT — 任务失败

**核心问题：完全误解了任务意图。**

ChatGPT 将调研问题本身当作一个"提示词"来分析和优化，整篇报告的核心是在做 prompt engineering 分析（提示词分类、A/B 测试框架、优化建议），而非拓扑指标调研。约 40% 的篇幅与问题要求完全无关。

- **覆盖面**：仅 APLS、TOPO、clDice、Graph IoU、GED、Betti 误差等少数指标，损失函数几乎未涉及。可微最短路径/LogSumExp/Perturb-and-MAP 等全部缺失。
- **结构化信息**：完全没有按照问题要求的 20+ 字段提供信息。无公式、无复杂度分析、无代码链接。
- **引用**：使用内部行号标记（`【51†L7-L14】`），无可点击链接，不可追溯。
- **分类体系/优先级/工具库设计**：全部缺失。
- **唯一价值**：提到了 CAPE 损失（MICCAI 2025）和 Skeleton Recall Loss（Kirchhoff 2024）。

**结论：不具备参考价值，可忽略。**

### 2.2 Gemini — 中等质量，公式损坏是致命伤

- **覆盖面**：约 11 个指标 + 7 个损失函数，覆盖遥感/医学/通用三大领域，但仅达到问题要求的约 1/3。
- **结构化信息**：每个指标提供了基本的多维度描述（领域、输入形式、可微性、优缺点、入库建议），但缺乏问题要求的完整字段。
- **引用质量**：54 条参考文献，但引用编号混乱，来源混杂了正式论文和博客/Wikipedia。部分引用为二次来源。
- **公式**：**数学公式以 base64 编码图片嵌入，实际不可读。** 这是最大的硬伤——核心指标（APLS、clDice、soft-clDice、LogSumExp）的公式全部无法查看。
- **独特贡献**：
  - GED 的"强烈不建议纳入"警告（评分不可比、速度不可接受）
  - PH Loss 在 3D 体素上的内存爆炸预警（仅能处理 16×16 或 32×32 patch）
  - APLS 的"中介中心性"视角解读
  - Newton Losses 和 DataSP 的前沿方法提及

### 2.3 Kimi — 覆盖面最广，设计建议最全面

- **覆盖面**：15+ 个指标 + 12+ 个损失函数，是四份中覆盖最全面的。完整覆盖遥感、医学、通用图结构、图学习/可微优化四个子领域。
- **结构化信息**：提供了四维属性对比矩阵（基础属性、技术属性、计算属性、敏感性分析）。敏感性矩阵覆盖 6 种错误类型（断裂/伪连接/漏检/几何偏移/拓扑环/分支错误），这是其他调研没有的。
- **引用质量**：提供了论文索引和 8 个代码库表格，但部分引用不精确（"最新研究，2024"无具体作者/标题）。**TOPO-F1 归属有误**：归于 Bastani et al. (Sat2Graph, ECCV 2020)，实际原始出处是 Biagioni & Eriksson (2012)。
- **分类体系**：完整的七类分类，与问题要求完全对应，每类包含典型指标、损失、关键依赖、适用场景。
- **工具库设计**：最为详尽，覆盖了 package structure、metric API（`TopologyMetric` 基类）、loss API（`nn.Module`）、graph schema（`TopoGraph`）、batch evaluation（`BatchEvaluator`）、五层可视化、8 个 benchmark 数据集、6 项验证策略。
- **独特贡献**：
  - TOPO-F1 实现变体分析（"严格实现"vs"宽松实现"）
  - 实现困难与开源缺口分析（高引用但实现困难/速度慢/定义不统一/无开源代码四类）
  - cbDice（clDice 的半径感知改进）的提及
  - Fast Betti Loss 的量化性能对比（快 72.7 倍）

### 2.4 Perplexity — 实用导向，工程警告最有价值

- **覆盖面**：约 13 个方法（经过"精选"过滤），有意省略了不成熟或重复的方法。但遗漏了 GED、Hausdorff/Chamfer 距离、树编辑距离、可微 Euler 示性数等。
- **结构化信息**：总览表仅约 7 个字段（名称、领域、任务类型、输入形式、是否需 graph/skeleton、可微性、用途）。**没有公式、没有核心思想描述、没有优缺点分析。**
- **引用质量**：64 条脚注，多为顶会论文 PDF 直链和 arXiv 链接，可追溯性在四份中最好。
- **独特贡献**：
  - **"论文引用多但工程坑大"警示清单**：标注了 TOPO-F1（定义不统一）、PH-based loss（C++ 依赖、3D 成本高）、Homotopy warping（debug 难）、diff shortest path（数值复杂）四类"advanced/experimental"方法
  - **"推荐组合"分层策略**：图级拓扑 → 中心线级拓扑 → mask 拓扑 → 几何-拓扑混合四层互补体系
  - **v0.1 的"无 C++/PH 依赖"约束**：确保 `pip install` 即可用，非常务实
  - 按表示形式（representation）而非领域组织分类，对代码模块化更有指导意义

## 五、交叉对比：优先级建议

| 版本 | Gemini | Kimi | Perplexity |
|------|--------|------|------------|
| v0.1 | clDice, soft-clDice, Skel P/R, Graph IoU, Skel Recall Loss | Dice/IoU/F1, clDice, APLS, TOPO-F1, Betti 数误差, CCE, soft-clDice | CC metrics, clDice, centerline Dice, Skel P/R, APLS, basic graph stats |
| v0.2 | APLS, TOPO-F1 | Betti 匹配, cbDice, Skel P/R, PH Loss, Graph IoU, 测地距离损失 | soft-clDice, Skel Recall Loss, TOPO-F1, Graph IoU, CTS, DT-based loss |
| v1.0 | Betti Matching, PH Loss, LogSumExp/Newton | diff 最短路径, GED, Perturb-and-MAP, TED, 完整 PH 管线 | PH/Betti 模块, CAPE, diff shortest path |

**关键分歧：APLS 和 TOPO-F1 应归入 v0.1 还是 v0.2？**
- Gemini：v0.2（认为图构建和节点吸附算法复杂度高）
- Kimi：v0.1（认为有成熟开源实现可参考）
- Perplexity：APLS 归 v0.1，TOPO-F1 归 v0.2（认为 TOPO-F1 定义变体多，实现复杂度高）

**对于本项目的建议**：APLS 已确定为首批实现指标，应归入 v0.1。TOPO-F1 实现难度确实更高（定义不统一），可考虑 v0.1 先实现一个参考 Sat2Graph 的标准化版本。

## 六、对工具库设计的关键启示

### 6.1 所有调研一致认同的设计原则

1. **按表示形式（representation）分层**，而非按领域分层
2. **指标（metric）与损失（loss）分离设计**
3. **Graph schema 统一**：`TopoGraph` 数据结构，兼容 NetworkX
4. **Metric API**：函数式接口，与 scikit-learn/torchmetrics 一致
5. **Loss API**：继承 `torch.nn.Module`，支持与 BCE/Dice 组合

### 6.2 来自 Perplexity 的务实建议

- v0.1 **不应依赖 C++ 或持久同调库**，确保 `pip install` 即可用
- TOPO-F1 的"定义不统一"问题需要在文档中明确说明采用了哪个变体
- "推荐组合"策略：不同任务场景提供预配置的指标组合

### 6.3 来自 Kimi 的详细建议

- `TopologyMetric` 基类 + 输入类型自动检测
- `BatchEvaluator` 多进程并行评估
- 五层可视化体系（骨架级/图级/路径级/持续图级/报告级）

### 6.4 来自 Gemini 的预警

- **GED 不应纳入**：评分不可比、速度不可接受
- **PH Loss 在 3D 上有内存爆炸问题**：只能在小 patch 上运算
- **Betti Matching 需要 C++ 后端**：Python 实现不可行

## 七、各模型在 TOPO-F1 归属问题上的错误

| 模型 | TOPO-F1 归属 | 是否正确 |
|------|-------------|---------|
| ChatGPT | 未明确说明 | N/A |
| Gemini | He et al. (RoadRunner, ACM SIGSPATIAL 2018) | ❌ |
| Kimi | Bastani et al. (Sat2Graph, ECCV 2020) | ❌ |
| Perplexity | 未明确指向原始论文 | N/A |

**正确答案**：TOPO 指标由 **Biagioni & Eriksson (2012)** 在 "Map Inference in the Face of Noise and Disparity"（ACM SIGSPATIAL GIS 2012）中提出。He et al. (RoadRunner, 2018) 和 He et al. (Sat2Graph, 2020) 是后来的使用者/推广者。

**这说明大模型在学术溯源方面存在系统性偏差**——倾向于引用知名度更高的论文而非真正的原始出处。在工具库的文档中应特别注意这一点。

## 八、结论与建议

### 推荐阅读优先级

1. **Kimi** — 首选参考。覆盖面最广、工具库设计最详尽、敏感性分析独有。
2. **Perplexity** — 补充参考。工程警告最有价值、引用可追溯性最好、v0.1 无 C++ 依赖的设计原则非常务实。
3. **Gemini** — 部分参考。GED/PH Loss 的预警有独到价值，但公式损坏严重影响了可用性。
4. **ChatGPT** — 可忽略。

### 下一步行动建议

1. 以 Kimi 的分类体系为基础确定模块划分
2. 以 Perplexity 的 v0.1/v0.2/v1.0 划分为基础确定实现路线（调整 APLS 至 v0.1）
3. 以 Kimi 的敏感性矩阵为参考设计测试用例
4. 以 Kimi 的工具库设计建议为参考确定 API 风格
5. 以 Perplexity 的"工程坑"警示清单为参考确定实现难点
6. 所有指标在文档中标注原始论文出处，避免"二次引用"错误
